**主要问题**

1. [outputs/flan_t5_baseline/test/predictions.csv](/D:/PyCharmProjects/comment_sa/outputs/flan_t5_baseline/test/predictions.csv) 这批结果是完整的，但模型几乎不预测 `neutral`。  
统计上：

- predicted `negative`: `155,905`
- predicted `positive`: `98,912`
- predicted `neutral`: `2,954`

而 test 集里真实 `neutral` 有 `56,639` 条。  
所以它不是“偶尔中性预测差”，而是**系统性回避 neutral**。

2. `neutral` 类基本崩了，是这批结果最核心的问题。  
从 [per_class_metrics.csv](/D:/PyCharmProjects/comment_sa/outputs/flan_t5_baseline/test/per_class_metrics.csv) 看：

- negative F1: `0.7063`
- positive F1: `0.6131`
- neutral F1: `0.0345`

其中：
- neutral precision: `0.3480`
- neutral recall: `0.01815`

也就是说，真实中性样本里只有不到 `2%` 被识别成 neutral。

3. T5 的 accuracy 看起来比 BERT 高，但这有很强的“类别塌缩”成分。  
[metrics.json](/D:/PyCharmProjects/comment_sa/outputs/flan_t5_baseline/test/metrics.json) 显示：

- Accuracy: `0.5946`
- Macro F1: `0.4513`

这个组合本身就很说明问题：
- accuracy 不低
- 但 macro F1 被拉下来了

原因就是模型主要在 `negative/positive` 两类之间分，几乎放弃 `neutral`。  
所以这个结果不能简单说“比 BERT 好很多”，更准确地说是：

- 它在 overall accuracy 上更高
- 但在三分类平衡表现上并不好
- 尤其 `neutral` 极差

4. 生成输出里确实存在非标准标签，但这不是主要矛盾。  
`parse_error=True` 的一共 `2,598` 条，占总量不高。  
常见非标准输出有：

- `sentimental` `1651`
- `sentiment` `626`
- `i`
- `a`
- `i like it`
- `love`

这些说明 prompt 解析规则不是完美，但它们的量级还不足以解释 neutral 全面崩掉。  
真正主因还是：**模型本身倾向把评论判成 positive/negative，而不是 neutral**。

5. 从混淆矩阵看，真实 neutral 大量被打成 negative 或 positive。  
矩阵是：

- true negative -> predicted negative: `94,450`
- true negative -> predicted positive: `16,681`
- true negative -> predicted neutral: `416`

- true positive -> predicted negative: `30,292`
- true positive -> predicted positive: `57,783`
- true positive -> predicted neutral: `1,510`

- true neutral -> predicted negative: `31,163`
- true neutral -> predicted positive: `24,448`
- true neutral -> predicted neutral: `1,028`

最关键的一行是最后一行：
- `56,639` 个真实 neutral
- 只有 `1,028` 个被预测成 neutral

这说明它几乎把 neutral 当成“没有必要输出的类别”。

**为什么会这样**

更可能的原因有三层：

- `google/flan-t5-base` 不是专门的 multilingual sentiment classifier
- 你现在的 prompt 很短很直接，但对 `neutral` 的定义不够“拉开边界”
- comment 数据本身有大量短文本、多语言、弱情绪、上下文不足样本，生成式模型很容易默认往正负两边靠

也就是说，这更像是：
- **模型与任务适配问题**
- 再加上一点 **prompt 设计问题**
- 不是代码算指标出了错
